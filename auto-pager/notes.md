# 自动翻页（auto-pager）开发笔记

## 做什么

论坛帖子列表、搜索结果、文章列表这类分页页面，滚到离底部不到 2 屏时自动加载下一页，拼到当前页下面：

- 自动找「下一页」：`<link rel="next">` / `<a rel="next">` → 文字、`aria-label`、`title`（下一页、下页、›、»、Next、Older posts…）→ 分页条里当前页码的后一个
- 不会把「下一篇 / 下一章 / Next post」这种文章之间的导航当成下一页
- 自动找内容区域（帖子列表、搜索结果列表），只搬内容，不搬页头页脚侧栏
- 每页前插一条「第 N 页」分隔线（链接到那一页的原地址），页面上的分页条换成最新一页的
- 相对链接转绝对地址、懒加载图片写回 `src`、GBK 编码的老论坛不乱码
- 加载中提示；失败显示原因和「重试」按钮；到最后一页 / 绕回旧页 / 到上限时写明原因
- 菜单：启用/停用（本站）、立即加载下一页、停止/继续（本页）、地址栏跟随当前页（默认关）
- 内置站点规则：Discuz! 帖子列表与帖子内容、Bing 搜索、百度搜索

`@match` 是全站，`@noframes` 不进 iframe。只请求同源页面（`fetch`，带 cookie），所以不需要 `@connect`。

## 怎么实现的

| 模块 | 做法 |
|---|---|
| `SITE_RULES` | 站点规则表：`host` / `url` / `when`（页面上存在某选择器）全满足的第一条生效；`next` / `content` / `pager` 三个选择器各自可选，没写或没命中的项照常走通用识别 |
| `Finder` | 输入任意文档（当前页，或解析出的下一页）+ 它的 URL，按「规则 → rel=next → 文字 → 页码」顺序找；每一步都过同一套判据（同源 http(s)、不指回本页、不是文章导航、不是 disabled） |
| `Content` | 内容容器 = 子元素里「同类」（同 tag + 同类名，去掉带数字的类名）最多、文字量最大，并且在下一页同一路径下也存在的元素。路径从最近的稳定 id 起逐级 tag + 类名，同一选择器命中多个时记下标 |
| `Fixer` | 导入前修正：`href` / `src` / `action` / `poster` / `srcset` 按下一页地址转绝对；`data-src` 等懒加载属性写回 `src`；删掉 `<script>` |
| `Loader` | 滚动（rAF 节流）时检查剩余高度；`fetch` → `ArrayBuffer` → 按编码解码 → `DOMParser` → 补 `<base>` → 识别 / 拼接 / 换分页条 → 找下一页。状态条、去重、上限、地址栏跟随都在这里 |
| `Menu` | 菜单文字带当前状态，切换后注销重注册；没有 `GM_unregisterMenuCommand` 时退化成固定文字只注册一次 |
| `Store` | GM 存储。`site:<hostname>` 存本站停用，`settings` 存全局的地址栏跟随开关 |

### 「下一页」和「下一篇」怎么区分

判据是三条，任一命中就不算：

1. 文字 / `aria-label` / `title` 里有「下一篇、下一章、下一节、下一条、下一集……」「上一 / 前一 / prev / newer」「next post / article / chapter……」。
2. 链接在文章导航容器里（类名或 id 含 `post-navigation`、`post-nav`、`entry-nav`、`nav-single`、`prev-next` 等）。
   WordPress 的 `next_post_link` 输出的是 `<a rel="next">文章标题</a>`，文字里一个「篇」字都没有，只能靠容器认。
3. 文字匹配要求**去掉两侧装饰（空格、箭头、括号）后整段等于**「下一页 / Next / Older posts」之类的词，
   「下一篇：如何写脚本」「下一页的内容」都不算。

`rel=next` 也要过第 1、2 条：它不只用于分页。`<link rel="next">`（在 `<head>` 里）不过滤，那是分页的标准声明。

### 只有箭头的链接

Bootstrap 的「« ‹ 1 2 3 › »」里 `›` 是下一页、`»` 是尾页；WordPress 等的「» 下一页」里 `»` 又是下一页。
所以 `›` / `>` 记 2 分，`»` / `>>` / `→` 记 1 分，文字记 3 分，取最高分里文档顺序第一个。

### 页码推断

当前页码 = 纯数字、不是链接（或者自己 / 上两级带 `aria-current="page"`、`current` / `active` / `cur` / `on` 等类名）的元素。
它往上 4 级内必须有一个含 ≥2 个纯数字链接的祖先（分页条），再在这里面找文字为 N+1 的链接。
列表里的回复数、楼层号也是「不是链接的数字」，靠「附近有一串数字链接」这一条和当前页码分开。

## 关键的坑

1. **内容容器只看当前页会被首页独有的结构骗走。** 首页的编辑推荐、置顶公告区文字往往比帖子列表还多。
   所以等下一页拿回来，候选按分数排好、逐个去下一页的同一路径下找，找得到且里面有同类子元素的才算。
2. **DOMParser 出来的文档 `baseURI` 是当前页。** 第 2 页里的相对链接会按第 1 页解析：
   `?page=3` 碰巧对得上，`/blog/page/2/` 里的 `../../a.html` 就错了。解析后补一个 `<base href=下一页地址>`
   （已有 `<base>` 的按下一页地址把它转成绝对的），之后 `Finder` 和 `Fixer` 都按它解析。
3. **导入的节点相对地址会改按当前页解析。** 所以导入前就要转成绝对地址。纯 `#锚点` 不动 ——
   内容已经在本页了，锚点指向本页才对；`javascript:` / `mailto:` 也不动。
4. **懒加载图片不会自己加载。** 页面上的懒加载脚本只观察首屏时就存在的 `<img>`，后拼进来的永远停在占位图。
   有 `data-src` / `data-original` / `data-lazy-src` / `data-actualsrc` / `file`（Discuz）等就直接写进 `src`，`data-srcset` 写进 `srcset`。
5. **`res.text()` 一律按 UTF-8 解。** GBK 论坛拿回来的第 2 页全是乱码，连「下一页」三个字都认不出，翻一页就断了。
   改成 `arrayBuffer()` + `TextDecoder`，编码依次取 Content-Type 头 → 前 1KB 里的 `<meta charset>` / `http-equiv` →
   当前页的 `document.characterSet`。编码名写错（`utf8mb4` 之类）`TextDecoder` 会抛 `RangeError`，退回 UTF-8。
6. **请求失败后每帧重试。** 拼接（或失败）后会再 `check()` 一次，好让很短的页面一口气补够长度；
   失败时如果也走这条路，人还停在底部就立刻再请求，rAF 驱动下一秒六十多次（测试实测）。
   失败后记下错误，自动加载停下，等用户点「重试」。
7. **死循环。** 有的论坛最后一页的「下一页」绕回第 1 页；有的页码越界会 302 回最后一页。
   已加载 URL 记账（含 `res.url`，即跳转后的最终地址），请求前、跳转后各查一次。
8. **分隔线的标签要和列表项匹配。** `<ul>` 里放 `<div>`、`<table>` 里放 `<div>`，浏览器会把它挤出去或者渲染错位。
   列表项是 `<li>` 就用 `<li>`，是 `<tr>` 就用 `<tr><td colspan>`，是 `<tbody>`（Discuz）就用 `<tbody><tr><td>`。
   样式也不能给 `<tr>` 加 `display: block`，落在 `<td>` 上。
9. **分页条从「下一页」链接出发找，不按类名找。** 页面上（内容区以外）指向下一页 URL 的链接，往上 4 级内第一个
   含 ≥2 个链接、又不包住内容区的祖先。`rel=next` 是 `<head>` 里的 `<link>` 时也能找到。
   同一路径命中多个（顶部 + 底部）就逐个换成下一页对应的。
10. **只搬「第一个到最后一个同类子元素之间」的部分。** 下一页容器里的表头行、容器内的分页条、末尾的清除浮动都不要，
    中间夹着的不同类元素（置顶帖、广告位）照搬。下一页接在上一次插入的最后一个节点后面，不是容器末尾 ——
    当前页容器末尾可能也有分页条。
11. **到上限只停自动，不丢下一页地址。** 菜单「立即加载下一页」还能一页一页往后拼。
12. **地址栏跟随用 `replaceState`，带上原来的 `history.state`。** `pushState` 会往「后退」里塞几十条历史；
    丢掉 `history.state` 的话 SPA 路由回退时恢复不了。默认关：改地址栏会让「刷新」直接回到第 N 页，不是每个人都想要。

## 已知限制

- 只认 `window` 滚动。内容在内层滚动容器（`overflow: auto` 的 div）里的站点，滚到底不会触发；可以用菜单「立即加载下一页」。
- 只处理服务器直出的分页页面。内容靠 JS 渲染的页面（SPA、Google 搜索）`fetch` 回来是空壳，认不出内容区就停下并提示。
- 页面上的脚本不会对拼进来的内容重新绑定事件（点赞按钮、展开全文、图片灯箱等可能不响应），`<script>` 也不搬。
- 同一页的不同 URL（`/list` 和 `/list?page=1`）去重认不出来，最后一页绕回 `?page=1` 时会多拼一页重复内容，然后才停。
- 下一页的分页条不在当前页同一路径下（结构变了）时，旧的分页条留着不换。
- 拼进来的内容里如果有和当前页重复的 `id`，页面自己的 `getElementById` 只会拿到第一个。
- 内置的 Discuz / Bing / 百度规则只用仿造结构的 fixture 测过（Discuz），真实站点**未实测**；百度、Bing 可能对 `fetch` 回人机验证页。
- 在真实 Tampermonkey 沙箱里 `fetch` 带 cookie 的行为、`history.replaceState` 的效果**未实测**（harness 没有沙箱）。

## 怎么跑测试

```bash
NODE_PATH=/path/to/node_modules node auto-pager/test/run.cjs
```

`NODE_PATH` 指向任意一个装了 `playwright` 的 `node_modules`（本仓库不带依赖）。
测试用 `tools/userscript-harness.cjs` 在 Playwright 里加载脚本、模拟 GM_*；页面全部用 `page.route`
挂在假域名 `https://bbs.example.com/...` 下，`test/fixtures/` 按 URL 分发（`list?page=2` → `list-2.html`，
`/blog/page/2/` → `blog-2.html`），不访问外网。

覆盖：rel=next 优先、文字匹配、`aria-label` / `title` 图标按钮、`› »` 箭头取舍、页码推断（含当前页是链接的写法、回复数不误认）、
「下一篇 / 下一章 / WordPress 文章导航」不误认、`javascript:` / 跨域 / `mailto:` / disabled / 纯 hash 链接跳过；
内容容器识别（不选菜单和侧栏、不选只在首页出现的推荐位）；滚动触发追加第 2、3 页与分隔线位置、首屏不预加载；
相对地址转绝对、懒加载图片、锚点与 `javascript:` 不动、脚本不搬；分页条替换（单条、顶部底部两条）；
循环链接、越界跳转、页数上限；请求 500 不连发、错误提示与重试、加载中提示、最后一页提示；
GBK（Content-Type 头 / `http-equiv` 两种声明，表格里的 `<tr>` / `<tbody>` 分隔线）；Discuz 站点规则；
四个菜单命令、本站停用刷新后生效、停止后手动加载、地址栏跟随（开启 / 默认关、不增加历史记录）。

测试里绕开的问题：

- **`page.route` 回 302 时，跳转后的请求不再经过 route**，直接走真实网络（假域名解析失败，`fetch` 报网络错误）。
  「越界跳转回旧页」那条用例自己起了一个会真跳转的本地 HTTP 服务（127.0.0.1，不出外网）。
- **GBK 字节**：node 没有 GBK 编码器、`TextEncoder` 只会 UTF-8，但 `TextDecoder('gbk')` 能解。
  测试把所有双字节码位解一遍反查出码表，把 UTF-8 存的 fixture 现场编码成 GBK 字节再发。
  第 1 页故意按 UTF-8 发：这样「按当前页编码解」两页都会乱码，解对了只能是真从头 / meta 里取到了编码。
- harness 的 GM 存储是页面 localStorage，只在同源内共享；「本站停用」只在同一个假域名下验证，测不出跨站隔离。
