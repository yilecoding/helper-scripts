# 网页变化监控（page-monitor）开发笔记

## 做什么

盯价格、库存、公告、成绩、工单状态：在页面上选一块区域，内容变化时通知。

- 菜单「选取要监控的区域」进入拾取模式：悬停高亮、点击选中、`↑` 或「↑ 父元素」扩到父元素、Esc 退出。
  选中后在确认条里选检查方式：
  - **定时抓取检查**：页面开着时按间隔（默认 5 分钟，最小 30 秒）用 `GM_xmlhttpRequest` 重新抓这个网址、
    `DOMParser` 解析、按选择器取文字比较。不刷新、不改动当前页面。
  - **在本页内观察**：给 JS 渲染、抓 HTML 拿不到内容的页面用，`MutationObserver` 盯着当前页面上的这块元素。
- 比较前规范化：折叠空白；可配置「噪声」正则（每行一个，比较前删掉，如 `更新于 \d+:\d+`）。
- 可选条件：变化后**包含 / 不含**关键词才通知；**数字变化**至少 N（或 N%）才通知 —— 取文字里第一个数字（如价格）。
- 通知：`GM_notification`。抓取型点通知开新标签看最新内容；本页观察的回到当前标签。
  页面右下角有角标：本页的监控数、未读变化数、检查失败数，点开面板。
- 面板（shadow DOM）：列出全部监控项（本页的排前面），启停、改间隔、立即检查、规则、历史、两步删除；
  显示上次检查 / 上次变化时间、当前值、失败原因。
- 每项留最近 20 条变化历史（时间、旧值、新值、是否通知及原因），面板里逐词 diff 高亮。
- 同一 URL 开着几个标签时，用「上次检查时间」做租约，一个间隔只抓一次。
- 失败不吞：抓取失败、选择器失效写进状态，面板和角标都显示；连续失败按 2 倍退避（最长 1 小时），
  连续第 3 次失败发一条「监控失效」通知。

`@match *://*/*`、`@noframes`。`@connect self`：只抓当前页面所在的站。

## 怎么实现的

| 模块 | 做法 |
|---|---|
| `Store` | GM 存储，**一个监控项一个键**（`mon:<id>`），`GM_listValues` 枚举 |
| `Text` | 自己走 DOM 取文字：跳过 `script`/`style`/`noscript`/`template`/`svg`，块级元素前后补空格；再折叠空白 |
| `Selector` | 稳定 id 优先（排除疑似随机的）；否则逐级拼「标签 + 最多 2 个稳定类名 + 必要时 `:nth-of-type`」，遇到有稳定 id 的祖先就以它为根，每拼一级试一次唯一性 |
| `Picker` | 捕获阶段监听 `mousemove`/`click`/`keydown`，吞掉页面的点击类事件；高亮框 `pointer-events: none` |
| `Rules` | 噪声正则、关键词、数字阈值。噪声只在比较时去掉，存储和显示的是原文 |
| `Diff` | 分词（英文单词 / 数字一个词，汉字一字一词，空白一段，符号单个）→ 剥掉相同头尾 → 中间段 LCS |
| `Checker` | `fetchText` 抓取取文字；`apply` 和存储里的最新值比、记历史、决定通知；`calibrate` 新建后校准；`fail` 记失败 |
| `Observer` | 一个 `MutationObserver` 观察整个 `body`，防抖 1 秒、持续变化最多等 5 秒，然后按选择器重新找元素比较 |
| `Scheduler` | 每 5 秒看一次本页的抓取型监控项谁到点；到点先认领再确认（租约），连续失败时间隔按 2 的幂拉长 |
| `Panel` | 面板与角标，同一个 shadow root（宿主挂在 `<html>` 下）；每轮调度时重绘一次，看到别的标签写进存储的结果 |

## 关键的坑

标注「实测」的是测试里复现过的；「推断」的是按机制推出来、没在真实 Tampermonkey 里验证过的。

1. **不能用 `innerText` 取文字（实测）。** `DOMParser` 出来的文档没有布局，`innerText` 退化成 `textContent`：
   `<script>` 的内容算进去，`<li>A</li><li>B</li>` 粘成 `AB`（在 Chromium 里对解析文档跑过）。
   基线在活页面上取、检查时在解析文档上取，两边必须是同一套规则，所以自己走 DOM。
   代价：`display:none` 的文字两边都会算进去（解析文档里本来也看不出哪些隐藏）。
2. **活页面和服务器直出的 HTML 不一样（实测）。** 站点脚本会往元素里补字（「有货」→「有货（剩 3 件）」），
   拿活页面的文字当基线，第一次定时检查就报一个假变化。新建后立即抓一次校准。
3. **`:nth-of-type` 在两份文档里会错位，而且是静默的（实测，修过）。** 站点脚本在 `body` 开头插一条 Cookie 提示，
   活页面上的 `div:nth-of-type(3)` 在服务器 HTML 里是另一个元素 —— 选择器照样命中、照样取到文字，
   只是盯着的是页脚，用户关心的价格变了永远不报。校准时拿选中时的文字去核对：
   命中的文字一样就用；不一样但抓到的文档里正好有一个元素文字相同，就按抓到的文档重新生成选择器；
   相近（一方包含另一方，或逐词相同部分过半）当作前端补过字；都不是就暂停并说明，不猜。
4. **类名能区分时不加序号（实测）。** 序号是选择器里最脆的部分，前面插一个同类元素就错位。
   只有兄弟里有同标签同类名的才加 `:nth-of-type`。
5. **随机 id 要排除（实测）。** 哈希串（`a8f3k2x9q1b7`）、React `useId`（`:r3:`）、长数字流水号、
   `ember123`/`radix-`/`headlessui-` 之类前缀，下次渲染就变。判定宁可错杀：错杀只是选择器长一点。
6. **数字阈值要和「上次通知时」比，不能和上次检查比（实测）。** 价格每次跌 4 块、阈值 10 块时，
   和上次检查比永远不够，累计跌了 10 块也不响。
7. **噪声只在比较时去掉（实测）。** 只有时间戳变了不算变化，但显示用的原文照样更新成最新的。
8. **本页观察要观察整个 body（实测）。** 框架重渲染常把整块节点换掉，盯着旧元素的观察器就再也收不到东西了。
   每次安静下来按选择器重新找。持续变化的页面（轮播、计时器）防抖永远等不到安静，所以有最长等待。
9. **同一 URL 多开标签会重复抓（实测）。** 各标签的调度器各自到点，开两个标签就是两份请求。
   到点时先把「上次检查时间」写成现在、署上标签 id，别的标签看到「刚检查过」就跳过。
   首轮调度随机错开，避免恢复会话时几个标签同一刻到点。
10. **认领后要等一下再确认（推断）。** 真实管理器里 GM 存储跨标签同步是异步的，两个标签可能同时认领；
    等 300ms 读回来，名字被覆盖掉的那个让出。harness 的存储是同步的，测不出这个窗口。
11. **一个监控项一个键（推断）。** 存成一个数组的话，两个标签各自读改写整个数组，后写的会把先写的改动覆盖掉。
12. **比较时从存储重新读（推断）。** 另一个标签刚记下的新值，这边再检查到同样的内容就不会再通知一次。
    主要防的是两个标签都在「本页观察」同一块内容；测试里只测了抓取型的租约，这条没有单独测。
13. **定时重绘不能冲掉正在输入的内容（推断）。** 面板每轮调度重绘，焦点在输入框里时跳过；
    规则编辑另有草稿，失焦后重绘也不丢没保存的输入。
14. **找不到元素是失败，不是「变成了空」。** 登录失效、页面改版时抓到的页面里没有这个元素，
    当成空文字的话会发一条「XX → （空）」的假通知，恢复后再发一条（推断）。
    现在的行为是记失败、旧值保留、不通知（实测）。

## 已知限制

- **抓取型只在有该 URL 的标签页开着、且脚本在运行时才检查。** 用户脚本没有常驻后台；关掉标签、
  关掉浏览器就停了。刻意只在「该 URL 的标签页」里检查，而不是任意标签页都抓全部监控项：
  否则开十个标签就是十份调度在抢，抓别的站还要额外的跨域授权。
  面板里别的页面的监控项不能「立即检查」，要到该页面上点。
- 后台标签页的计时器会被浏览器节流（Chrome 隐藏久了的标签大约一分钟才跑一次计时器），
  30 秒的间隔在后台实际会变长。**未实测。**
- `@connect self`：只能抓当前站点。抓取时被重定向到别的域名（例如统一登录页）会失败。**未实测。**
- 依赖 `GM_xmlhttpRequest` 默认带 cookie 才能抓到要登录的页面（成绩、工单）。**未在真实 Tampermonkey 里实测。**
- 只在 `<meta charset>` 里声明 GBK 的老页面，`responseText` 可能乱码。**未实测。**
- 抓取型看不到 JS 渲染的内容，要用「在本页内观察」。本页观察只在标签开着时有效；
  重新打开该页时会把当前内容和上次记下的比一次（**未单独测**）。
- 本页观察时，内容先显示「加载中…」再出真内容的页面会报两次变化（空文字会跳过，占位文字跳不过）。
- 通知点击：本页观察的变化调用 `window.focus()`，浏览器不一定真的切到那个标签。**未实测。**
- 逐词 diff 对中文按字切，没有分词；超长文字（两边词数之积超过 150 万）退化成整段替换。
- 选择器是启发式：随机 id 判定可能误判；页面大改版后选择器失效，只能重新选。
- 看不到 iframe（`@noframes`）和 Web Components shadow DOM 里的内容。
- 别的标签写进存储的结果，这边最多 5 秒后（下一轮调度）才在面板上看到 —— 没用 `GM_addValueChangeListener`。

## 怎么跑测试

```bash
NODE_PATH=/path/to/node_modules node page-monitor/test/run.cjs
```

`NODE_PATH` 指向任意一个装了 `playwright` 的 `node_modules`（本仓库不带依赖）。
页面用 `page.route` 按正则挂在假域名 `https://shop.example.com/...` 下，不访问外网。
测试里的「服务器」是一个 `site` 对象：页面导航和脚本的 `GM_xmlhttpRequest`（harness 的 `xhr` 选项）都从它取内容，
改 `site.files` 就等于服务器上的页面变了。定时逻辑用 `page.clock` 推进，不真等。

覆盖：稳定 id / 随机 id 跳过 / 类名唯一时不加序号 / `:nth-of-type`、拾取（点链接不跳转、父元素、Esc）、
保存基线、抓取型到点检测变化并通知、点通知打开该页、校准基线、面板（启停、间隔下限、立即检查、两步删除）、
角标未读、空白与噪声正则（含无效正则报错）、关键词包含/不含、数字阈值（绝对值、百分比、千分位、数字消失）、
历史 20 条封顶与逐词 diff、本页观察（改文字、整块重渲染、无关变化、持续变化的最长等待）、
两个标签的租约与接手、选择器失效的错误状态、失败退避与「监控失效」通知、恢复、`:nth-of-type` 错位校正与暂停。

harness 和真实 Tampermonkey 的差异，影响到的地方：

- GM 存储是页面的 localStorage，读写同步、同源共享。测多标签要在**同一个 browser context** 里开两个页面
  （`browser.newPage()` 每次是新 context，存储不共享）。真实管理器里跨标签同步的异步窗口测不出来，
  租约的「认领后确认」那一步没有被真正考验过。
- `h.gm(page)` 把记录序列化回 node，通知里的 `onclick` 函数会丢掉；点通知要在页面里调
  `window.__gm.notifications[i].onclick()`。
- `page.clock` 接管了页面里的计时器，等待改在 node 这边轮询（`waitFor`），推进时钟后再给 xhr 桥一点真实时间跑完。
