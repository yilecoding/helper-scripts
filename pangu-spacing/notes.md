# 中英文自动加空格（pangu-spacing）开发笔记

## 做什么

在网页里的中日韩文字和英文字母、数字之间自动加一个空格（「盘古之白」）：

- 「今天用React写了2个组件」→「今天用 React 写了 2 个组件」
- 跨元素也加：「中文<b>English</b>中文」→「中文 <b>English</b> 中文」，空格加在 `<b>` 外面
- `100%`、`C++`、`#标签`、`$100`、URL、邮箱、路径、版本号、时间不会被拆坏；全角标点旁不加
- 代码（`code`/`pre`/`kbd`/`samp`）、表单控件、可编辑区、`svg`/`math` 不碰
- 只改 `Text.nodeValue`，不碰 `innerHTML`：页面结构、事件绑定、框架攥着的节点引用都不变
- 动态加载的内容也处理（MutationObserver），大页面放进空闲时间分批做
- 菜单：本站停用/启用（停用立即还原本页）、立即处理整页、处理选中区域、自定义跳过选择器、
  title/alt 属性开关
- 默认排除代码托管站的代码视图、在线文档和在线代码编辑器

`@match` 是全站，`@noframes` 不进 iframe，`@run-at document-idle`。

## 规则表

规则在脚本的 `RULES` 里，**按顺序**对整段文字做 replace。每条规则只在两个非空白字符之间
**插入一个空格**，不删、不换任何字符 —— 「已有空格不重复加」由此天然成立，跨节点判断也靠这一点
（见下文）。

| # | 规则 | 例子 | 不动的例子 |
|---|---|---|---|
| 1 | `#话题#`（含 CJK）整体当一个词，两侧挨着文字加空格 | 看#话题#很好 → 看 #话题# 很好 | `C#和F#`（前面是字母，# 是后缀） |
| 2 | CJK + 字母数字 | 用React → 用 React | |
| 3 | 字母数字 + CJK | 3个 → 3 个 | |
| 4 | 后缀符号 `+ # % ° ℃` 跟前面的词走，空格加在符号后 | 100%以上 → 100% 以上；C++写 → C++ 写 | `100%`、`C++` 内部 |
| 5 | 前缀符号 `# @` 跟后面的词走，空格加在符号前 | 看看#标签 → 看看 #标签；联系@张三 → 联系 @张三 | `#标签`（# 和标签之间不加） |
| 6 | `$` 后面是数字才当金额 | 花了$100块 → 花了 $100 块 | `变量$PATH`（变量名） |
| 7 | 半角 `(` 前、`)` 后挨着 CJK 加空格，括号内侧不加 | 用(括号) → 用 (括号) | `用（全角括号）`、`f(x)` 内部、`文字[1]` |
| 8 | 半角双引号配对，引号外侧挨着 CJK 加空格 | 说"hello"然后 → 说 "hello" 然后 | 不配对的 `"`、单引号 |
| 9 | 字母数字后的半角标点 `.,!?;:` 再接 CJK，标点后加空格 | Hello,世界 → Hello, 世界 | `中文,English`（CJK 后的半角标点不管） |

**不在表里 = 不加**：运算符和连字符 `- + = * / | \ & ^ ~ < >` 挨着 CJK 一律不加（「北京-上海」「是/否」
「苹果+香蕉」），全角标点 `，。「」（）《》“”` 等不在 CJK 字符集里所以两侧都不会加，emoji 也不加。

**CJK 字符集**（`C`）：部首、々〇、平假名片假名（不含中点「・」）、注音、扩展 A、基本区、兼容表意、
半角片假名、韩文字母与谚文音节、扩展 B–H（补充平面，正则要带 `u`）。刻意排除 `\u3000-\u303f`
（标点）、`\u3300-\u33ff`（㎡ ㎏ 这类单位）、`\uff00-\uffef`（全角 ASCII 与全角标点）。

**字母数字**（`A`）：ASCII 字母数字 + 拉丁扩展（café）、希腊（α）、西里尔（Москва）。

**保护片段**（`PROTECT`，在规则之前做）：URL（`scheme://` 和 `www.`）、邮箱、Unix 路径（至少两段，
或 `~/`）、Windows 路径、版本号/小数/IP（`v1.2.3-beta.1`）、时间（`12:30:45`）。
做法是只把片段的**内部**换成占位符，首尾字符留在原处 —— 片段两侧该不该加空格照常由规则决定
（「版本v1.2.3发布」→「版本 v1.2.3 发布」），内部一个字都不会被规则看到。

## 怎么实现的

| 模块 | 做法 |
|---|---|
| `spacing(text)` | 没有 CJK 直接返回；`hold()` 换掉保护片段内部 → 依次跑 `RULES` → 换回来。纯函数，node 里直接测 |
| `junction(left, right)` | 两段相邻文字（分属两个节点）的交界要不要加空格。见下 |
| `Skip` | 内置跳过选择器 + `CONFIG.extraSkipSelector` + 菜单里填的（GM `settings.skip`），写错的不生效 |
| `collect(root)` | 递归收集成序列：文字节点 / 断点（`null`）/ 原子元素（行内 code）/ 属性项 |
| `runItems` | 逐项 `spacing`，再和前一项做交界判断；`state.prev` 跨批次保留，分批不影响交界 |
| `Queue` | 变化所在的「块」进队列，`requestIdleCallback` 分批跑（每 200 项看一次剩余时间） |
| `observe()` | `childList + characterData + subtree`；按节点去重；忽略自己的写入 |
| `Site` | GM `site:<hostname>` 存 `{ disabled }`，只存和默认（默认排除表）不同的选择 |
| `Settings` | GM `settings` 存 `{ skip, attributes }`，同样只存和默认值不同的项 |

### 跨节点：不另写一套规则

`junction(L, R)` 把两段拼起来跑**同一张规则表**，再把输出和输入逐字对齐：规则只会插空格，
所以输出 = 输入 + 若干空格，能对齐出每个空格插在哪；有一个正好插在交界处就是「要加」。
两侧各取 128 个字符做上下文（够装下一个 URL）。保护片段两侧**分开**算：节点边界本身说明
链接文字到此为止，`<a>https://a.com/x</a>中文` 不能把后面的中文也吃进 URL。

哪些相邻算「交界」：只在**行内元素**内连续的文字之间（`a b span em strong i u s del ins mark small
font abbr cite time…`）。块级元素、`br`、`img`、`button`、`sup`/`sub`（脚注角标「文字<sup>1</sup>」不该加）、
`q`（自己会画引号）、`ruby` 都是断点。被跳过的行内 `code`/`kbd`/`samp` 是「原子」：里面不动，
但两侧的文字照样和它比较，「使用<code>npm</code>安装」→「使用 <code>npm</code> 安装」。

### 空格加在哪一侧

1. 一侧是原子元素（code）：只能加在文字那侧。
2. 两侧都是文字：从各自的文字节点往上数到共同祖先，每层记 1，`a u ins del s strike mark abbr`
   这类会把空格也画出来的（下划线、删除线、底色）记 100，**代价小的一侧加**；一样就加在左边末尾。
   - 「中文<b>English</b>」→ 加在「中文」末尾（0 < 1）
   - 「项目<a>文档</a>English」→ 加在「English」开头（链接 100 > 0），空格不进下划线
   - 「点了<span>0</span>次」→ 两个空格都加在 span 外面。顺带的好处：框架只更新 span 里的数字时，空格不会被冲掉（有测试）

### 动态内容与防循环

- 变化只重跑它所在的**块**（往上找到第一个非行内元素）：交界判断不跨块，没必要重跑整页。
  删除节点也要重跑父块 —— 删掉中间的元素，两边的文字就变成相邻了。
- 防无限循环：写之前记下「改前 / 改后」（`WeakMap`）。观察到的 `characterData` 值等于我们写的 →
  自己触发的，忽略。即使不忽略也不会死循环（`spacing` 幂等，第二遍不写），忽略省的是重复计算。
- 防拉锯：值**又变回改前** = 页面把它改回去了。同一节点被改回去 3 次（`maxReverts`）就放手。
  实测：一个「守着自己文字」的页面（自己的 MutationObserver 一看到改动就写回原文），
  不放手的话 1.5 秒内来回了 91 次；放手后停在 3 次。
- 大页面：3000 段 × 5 个文字节点 ≈ 2 万个节点，首次处理分了 5～11 次空闲回调，240～290ms 处理完（几次实测）；
  加载后一次插入 6000 段，Long Tasks API 没有记录到超过 50ms 的任务。

### 停用即还原

改过的节点存 `WeakRef`（`Set` 里，定期清掉已回收的），停用时遍历：当前值还等于我们写的就写回改前的值；
页面之后又改过的不动。title/alt 属性同理。

## React / Vue 页面（一次性实测，不在测试套件里）

用本机现成的 React 19.2.8（react-dom/client 开发版，esbuild 打包）和 Vue 3.5.31（`vue.global.js`
开发版）各写了一个计数器页面，在 harness 里装上脚本跑：

| 场景 | 观察到的 |
|---|---|
| React / Vue 客户端渲染，点按钮更新状态 | 框架直接写 `nodeValue`（或替换文字节点），把空格冲掉；观察器收到后重新加上。控制台无报错 |
| React 19 SSR，`hydrateRoot` 晚于 `load`（脚本已经改过文字） | `onRecoverableError`：「Hydration failed because the server rendered text didn't match the client. As a result this tree will be regenerated on the client」—— **整棵树在客户端重建**（原来的 `<p>` 引用失效），新 DOM 再被脚本处理一遍。页面能用，但白丢了 SSR |
| Vue 3 SSR，`createSSRApp().mount()` 晚于 `load` | 每处不一致一条 `[Vue warn]: Hydration text content mismatch`，最后一条 `console.error`「Hydration completed but contains mismatches.」；Vue 把文字改回原样、元素保留，脚本再加回空格 |

结论：

- 脚本在 `document-idle`（load 之后）跑，首次处理还要等空闲回调，正常的 SSR 页面 hydrate 早已完成，碰不到上面的问题。
  只有 hydrate 拖到 load 之后的站（懒 hydrate、超大 bundle）会触发；遇到了就在那个站点停用。
- 框架只在自己的状态变化时写 DOM，不会读回 DOM 比对，所以不会和脚本拉锯；
  真有「写回原文」的（自己守着文字的页面），3 次后放手。

## 关键的坑

1. **全角标点旁不加空格，靠的是字符集而不是规则。** CJK 字符集里要刻意挖掉 `\u3000-\u303f`、
   `\uff00-\uffef`，否则「完成。Next」会被当成 CJK + 字母加空格。`\u30fb`（・）和 `\u3300-\u33ff`（㎡）同理。
2. **`#` 有三种身份。** `C#` 的后缀、`#标签` 的前缀、`#话题#` 的括号。话题规则要排在最前，
   而且前面紧跟字母数字时不算话题开头 —— 否则「C#和F#都」里的「#和F#」会被当成话题。
3. **URL 路径里允许 CJK。** 不然「…/wiki/C++教程」会拆成「C++ 教程」、「?q=React教程」拆成「React 教程」、
   「#小节」拆成「# 小节」，链接全坏（去掉保护后实测三条全坏）。代价是「访问https://a.com/了解更多」
   后半句被当成 URL、不加空格 —— 宁可少加，不可加坏。文件路径只认 ASCII 段：「/usr/local/bin下」的「下」是正文。
4. **占位符用 `\ufdd0`（非字符），不用私用区。** 图标字体把图标放在私用区，页面文字里真会有 `\ue000` 起的字符。
5. **扩展 B 的字是代理对。** 取邻居字符要按码点取（`codePointAt` / `Array.from`），`s[off - 1]` 只拿到半个字，永远匹配不上。
6. **`<option>` 要跳过。** 没写 `value` 的 option 提交的就是它的文字，加空格等于改了表单数据。
7. **只在 `[contenteditable]` 上用属性选择器不够。** 还要 `isContentEditable` 兜住继承来的可编辑状态
   和 `designMode`（这半条是按规范推的，没有单独测）；`contenteditable="false"` 的元素本身不可编辑，照常处理（有测试）。
8. **默认排除是按路径算的，SPA 换页不刷新。** 在 GitHub 代码视图打开、再点进 issue 页时，最早的版本
   因为「打开时没生效」根本没挂观察器，之后什么都不处理（测试先红了才修）。现在只要用户没手动停用本站，
   观察器就一直挂着，每批变化现查路径；从排除路径换出来时整页重跑一遍，菜单文字跟着更新。
9. **「被改回去」按节点去重再计数。** 我们写一次、页面写回一次，同一批记录里有两条，不去重就一次记两回。
10. **测试 fixture 里内联脚本的注释不能写 `</script>`。** 写了就提前结束脚本元素（踩过，结构签名测试因此一直对不上）。

## 已知限制

- 单引号不处理（和英文撇号分不开）；`-` 一律不加，所以「使用-v参数」只得到「使用-v 参数」。
- 跨节点交界只看行内元素；`display` 被 CSS 改过的元素（`<span style="display:block">`、`<div style="display:inline">`）
  按标签名判断，会多加（行尾空格，通常看不出来）或漏加。
- 两个相邻链接「<a>链接</a><a>Link</a>」之间的空格只能加进某一个链接里（不新增节点），会带下划线。
- 处理选中区域时按整个文字节点处理，不切开节点只处理选中的那几个字。
- title / alt 只在元素被收集时处理；页面之后改属性不会触发（没观察 attributes）。
- 看不到 Shadow DOM（Web Components）和 iframe（`@noframes`）里的文字。
- 自定义跳过选择器只影响之后的处理，已经加过的空格要刷新才会消失。
- 页面反复把同一段文字写回原样（哪怕是无心的定时重写）3 次后，那个节点就不再处理。
- 晚于 load 才 hydrate 的 SSR 页面会触发 hydration 不匹配（见上表），React 会重建整棵树。

## 怎么跑测试

```bash
NODE_PATH=/path/to/node_modules node pangu-spacing/test/run.cjs
```

`NODE_PATH` 指向任意一个装了 `playwright` 的 `node_modules`（本仓库不带依赖）。

- **文本规则**：脚本没有 `document` 时只导出纯函数（`spacing`、`junction`、`RULES`），
  测试用 `vm` 在 node 里加载，76 条输入 → 期望输出（含 URL、版本号、百分比、C++、#标签、
  全角标点、已有空格、日文、韩文、emoji、扩展 B 等反例）+ 幂等检查 + 13 条交界判断。
- **DOM**：用 `tools/userscript-harness.cjs` 在 Playwright 里加载脚本、模拟 GM_*；页面用
  `page.route(/^https:\/\/example\.com\//, …)` 挂在假域名下（GitHub、Google Docs 的默认排除也是这样模拟），
  fixtures 在 `test/fixtures/`，不访问外网。覆盖：跳过列表、DOM 结构签名 / 节点引用 / 事件绑定不变、
  跨元素边界（空格落在哪一侧）、动态插入 / 改文字 / 删中间元素、mutation 次数有界且会停、
  页面拉锯时放手、框架式更新、大页面分批、站点停用 / 还原 / 刷新保持、默认排除与 SPA 换页、
  立即处理整页、处理选区、自定义跳过选择器、title/alt 开关。

harness 和真实 Tampermonkey 的差异，影响到的地方：

- GM 存储在 harness 里是页面的 localStorage，按源隔离；所以「按站点存」只能检查存储键名
  （`site:example.com`、`site:github.com`）来验证，测不出跨站共享的 `settings`。
- harness 没有沙箱，脚本直接跑在页面上下文；真实环境里 `@grant` 了 GM_* 会进沙箱，
  `requestIdleCallback`、`WeakRef`、`MutationObserver` 都还在，但没有在真实 Tampermonkey 里跑过。
- `GM_unregisterMenuCommand` 在 harness 里是把记录置空，菜单重绘的顺序和真实扩展可能不同；测试按位置取第一项、第五项。
