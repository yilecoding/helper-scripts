# 网站使用时长统计与限制（site-timer）开发笔记

## 做什么

统计每个网站「真正在用」的时间，并可给站点设每日上限：

- **只算在用的时间**：标签页可见 + 窗口聚焦 + 最近 5 分钟内有键盘 / 鼠标 / 滚轮 / 滚动 / 触摸；
  有声音的视频或音频在播放时，不碰键鼠、窗口没聚焦（副屏看视频）也算
- **按主域名归并**：`www.`、`m.` 和其他子域名归到注册域名；`example.com.cn`、`bbc.co.uk` 这类二级后缀，
  `alice.github.io`、`xxx.vercel.app` 这类托管平台按各自的站点算
- **同一站点开多个标签只算一份**；跨本地零点的一段时间切到两天；电脑睡眠的那段不算
- **每日上限**：剩 5 分钟时右下角提醒一次；到了全屏遮罩「今日已用 X 分钟」，暂停页面上的视频音频，
  提供「再给 5 分钟」（每天最多 3 次）和「今天不再提醒」
- **统计面板**：今天 / 近 7 天各站点排行（CSS 条形图），行内改上限，导出 CSV
- **数据保留 30 天**，每天自动清理一次
- 菜单：打开统计面板、给当前站点设上限、暂停 / 恢复计时（全局）

`@match` 是全站，`@noframes` 不进 iframe，`@run-at document-end`。

## 怎么实现的

| 模块 | 做法 |
|---|---|
| `mainDomain` | 内置一张多段公共后缀小表（国家二级后缀 + 托管平台私有后缀），从长到短匹配，命中就再往前带一段；都没命中取最后两段。IP、`localhost` 原样 |
| `Activity` | 输入事件挂在 window 捕获阶段只记时间戳；`isActive()` 每次现读 `visibilityState` / `hasFocus()` / 媒体状态 |
| `Lease` | 每站一份租约 `lease:<站点>` = `{ id, ts }`，持有者每 5 秒续约，15 秒没续算过期 |
| `Timer` | 每秒 tick：上次 tick 到现在这段，两头都「在用且持有租约」才记进内存；攒满 15 秒或隐藏 / 失焦 / `pagehide` / 交出租约时落盘 |
| `Limit` | 每次 tick 比较「已落盘 + 内存里的」和上限；遮罩、提醒条都在 shadow DOM 里 |
| `Panel` | `GM_listValues` 扫出所有 `t:` 键按日期范围汇总；CSV 用 Blob + `a[download]`，带 BOM |
| `Cleanup` | 每天第一次 tick 时删 30 天以前的 `t:` / `f:` 键和一天没续过的租约 |
| `Menu` | 暂停开关存 GM（全局），菜单文字随状态变，整组注销重注册 |

### 存储键

| 键 | 值 | 谁写 |
|---|---|---|
| `t:2026-10-29:example.com` | 当天在该站点的毫秒数 | 只有该站点的租约持有者 |
| `f:2026-10-29:example.com` | `{ extends, quiet, warned }` 当天的限制状态 | 点遮罩按钮 / 提醒时 |
| `lease:example.com` | `{ id, ts }` | 见下 |
| `limits` | `{ 站点: 分钟 }` | 用户设置时 |
| `paused` / `cleanup` | 暂停开关 / 上次清理的日期 | |

时长**一天一站一个键**，不把一天所有站点放进一个对象：GM 存储没有事务，不同站点的标签页同时
读改写同一个对象，后写的会覆盖先写的。一站一键配合租约，同一时刻只有一个标签页写它。

### 多标签租约与竞争

- 「在用」的标签页每次 tick 试着拿租约：没人持有、持有者是自己、或者别人的已过期（`|now - ts| ≥ 15s`，
  用绝对值是防系统时间往回调后出现一份「未来的租约」永远不过期）才算拿到。
- **两头确认**：GM_setValue 在别的标签页里是异步可见的，两个标签页可能同时看到「没人持有」并同时写入。
  所以一段时间只有开头和结尾读到的租约都是自己才记上。存储收敛后只剩一个 id，输的一方下一次 tick
  读到别人的 id，那一段整段不算。宁可少算一秒，也不两边都算。
- 不在用（切走、失焦、空闲、卸载、遮罩出现、暂停）就主动释放，别的标签页下一次 tick 就接手；
  只有崩溃这种来不及释放的才靠 15 秒过期。被抢走时先把内存里的落盘。

### 为什么媒体播放能顶替焦点判定

需求原文是「可见且聚焦 + 最近有输入，播放视频算在用」。实现成：可见，并且（聚焦且最近有输入，**或**有声媒体在播）。
副屏放视频、主屏在别的窗口打字是常见用法，那段时间确实在看这个站。静音的媒体不算：
信息流里自动播放的静音视频、页面背景视频会让空闲判定永远不触发。

## 关键的坑

1. **睡眠判定要放在「记一段时间」的入口，不能只放在 tick 里。**（测试覆盖）醒来后先到的往往是
   锁屏解锁带来的 `blur` / `visibilitychange`，走 `stop()` 补记最后一段，不经过 tick。只在 tick 里查间隔，
   这条路径会把几小时的睡眠整段记进去（变异测试实测：去掉判定后两个睡眠用例分别记成 7220 秒和 10810 秒）。
2. **切回来那一刻就开始算，不等下一次 tick 确认。**（测试覆盖）最初「刚变活跃的那一秒不算」，
   每次切换丢最多 1 秒，测试里切几次就对不上；现在 `visibilitychange` / `focus` / 第一次输入 / `playing`
   都直接 `resume()`。已经在算的时候不能重置 `lastTick`，否则把上一个 tick 到现在这段丢了。
3. **失焦时先补记再看要不要接着算**：`blur` → `stop()`（补记 + 落盘 + 交租约）→ `resume()`（还在放视频就重新拿）。
4. **跨天按本地零点切**，用 `setHours(24, 0, 0, 0)` 找下一个零点；近 7 天用 `new Date(y, m, d - i)` 往回数，
   不减 86400000 —— 夏令时那天不是 24 小时（夏令时本身**未实测**，测试只用了东八区）。
   日期键不用 `toISOString()`，那是 UTC，东八区早上 8 点前会算到前一天。
5. **遮罩出现时要把焦点挪进遮罩。**（测试测出来的）遮罩期间在 window 捕获阶段拦截按键，
   焦点留在页面里的话 Tab / Enter 一起被吞，键盘用户够不着遮罩按钮。另外最初只 `preventDefault`
   页面以外的按键、放行遮罩上的，结果遮罩上的 Enter 照样冒泡到页面的监听。现在一律停传播，
   遮罩按钮上的只是不 `preventDefault`（按钮被 Enter 激活是默认行为，不靠监听）。
6. **导出 CSV 前先落盘。**（测试测出来的）面板排行把本标签页内存里没落盘的部分加上了，CSV 没加，两边对不上。
7. **遮罩期间页面再起播要压回去**：自动连播、播放器快捷键都会 `play()`，`play` 事件不冒泡，挂 document 捕获阶段。
   全屏的视频在 top layer，盖在任何 z-index 之上，遮罩时先 `exitFullscreen()`（**未实测**，headless 没测全屏）。
8. **宿主元素会被页面删掉**：SPA 重写 DOM 时把我们的宿主一起带走，遮罩就没了。每次 tick 超限时都会
   `mount()`，宿主不在文档里就补回去（测试覆盖）。
9. **「再给 5 分钟」之后不要弹「还剩 5 分钟」**：再给的 5 分钟本来就在提醒窗口里。提醒记的是「对哪个上限值提醒过」，
   再给时直接把新上限记成已提醒；用户改了上限会重新提醒。
10. **菜单文字要随暂停状态变**，`GM_unregisterMenuCommand` 后只重注册一项会跑到菜单末尾，所以整组重注册；
    别的标签页里切换的，tick 时发现存储里的值和自己不一致再刷新。

## 已知限制

- **崩溃 / 被强杀的标签页**：没落盘的最多 15 秒丢掉；它的租约要等 15 秒过期，这期间同站的其他标签页不计时（测试覆盖）。
- **交租约那一刻的并发写**：被抢走租约的一方落盘时，新持有者恰好也在落盘，读改写可能互相覆盖，
  丢掉其中一方的十几秒。窗口很小（新持有者第一次落盘在接手 15 秒后），**未实测**。
- **跨标签页的同步延迟**：Tampermonkey 里 GM 存储在标签页之间是异步同步的，「两头确认」假设一秒内收敛。
  实际延迟**未实测**（harness 的模拟存储是同步的 localStorage）。
- **空闲判定是事后的**：最后一次输入之后的 5 分钟照算（当作在阅读），离开电脑前那 5 分钟会被算进去。
- **看不到的媒体**：跨域 iframe 里的视频（`@noframes`，也读不到）、Web Components shadow DOM 里的、
  `new Audio()` 没挂进 DOM 的，都不会被当成「在播」；这类站点放视频时不碰键鼠，5 分钟后停止计时。
- **静音播放不算**：开着静音看带字幕的视频，5 分钟后停止计时。
- **只统计装了脚本的浏览器**，多设备不汇总；隐身窗口按 Tampermonkey 的设置可能单独存储（**未实测**）。
- 公共后缀表是精简版，表里没有的多段后缀（如 `co.il`）会归并到后缀本身（`co.il`）。
- 遮罩只是提醒性质：用户可以停用脚本、开发者工具删掉元素后在下一秒补回前操作。

## 怎么跑测试

```bash
NODE_PATH=/path/to/node_modules node site-timer/test/run.cjs
```

页面都挂在 `https://` 假域名下（`context.route(/^https:\/\//)` 拦下来回 fixture），不访问外网；
`video.html` 里的媒体是测试里生成的静音 WAV（`<video>` 也能放纯音频）。覆盖：元数据、主域名归并、
可见 + 聚焦、空闲、落盘频率、媒体、跨零点、睡眠、多标签租约（交接 / 崩溃 / 竞争）、上限提醒与遮罩、
再给 / 今天不再提醒、菜单设上限、面板排行 / 改上限 / CSV、30 天清理、暂停，以及上面几条边界情况。

和真实环境的差异，写测试时要心里有数：

- **假时钟**：每个 context 装 `clock.install` 后立刻 `pauseAt`，之后只有 `runFor` 才走。不停住的话页面加载期间
  假时钟按真实速度走，脚本启动时刻每次不同，崩溃用例偶发算出 64 秒而不是 60 秒（实际撞到过；
  原因是推断的：tick 与 `runFor` 的边界错开，最后一次续约早了一轮，租约提前过期）。
  睡眠用 `fastForward`（到期的定时器最多触发一次 = 醒来后的第一次 tick）和 `setSystemTime`（一个都不触发）模拟。
- **可见性 / 焦点**：headless 里永远是 visible / 有焦点，测试在页面上覆盖 `visibilityState` / `hidden` / `hasFocus`
  再手动派发事件。覆盖时没设值要回落到真实值：写死 `'visible'` 的话刷新时浏览器派发的真 `visibilitychange(hidden)`
  被读成「可见」，将卸载的页面又抢走租约（测试替身的问题，实际撞到过，不是脚本的）。
- **崩溃**：`page.close()` 不管 `runBeforeUnload` 都会触发 `pagehide`，模拟崩溃是在测试里先注册捕获监听把
  `pagehide` / `blur` / `visibilitychange` 吞掉再关。
- **GM 存储按源隔离**：harness 用页面的 localStorage 模拟，只在同源内共享；真实环境是全局共享。
  所以「跨站汇总」是把别的站点的 `t:` 键预置在同一个源下验证的；多标签用同一个 context 里的两个同源页面。
- 没用 `GM_addValueChangeListener`（暂停状态、上限每秒 tick 时现读），harness 不用补。
