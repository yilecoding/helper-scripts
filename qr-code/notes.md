# 页面二维码（qr-code）开发笔记

## 做什么

把电脑上的页面 / 链接 / 一段文字变成二维码，手机一扫就过去：

- **Alt+Q** 或菜单「当前页面二维码」：弹出当前页地址的二维码浮层；再按一次 Alt+Q、Esc、点浮层外面都能关
- 浮层里有文本框，改内容实时重绘；纠错等级 L/M/Q/H 一键切换（全局记住，默认 M）；
  信息栏显示版本、模式、已用 / 本版本容量，超出版本 40 时提示超了多少
- **下载 PNG**、**复制图片**（`ClipboardItem`，不支持或被拒绝时降级为下载）
- 菜单「选中文字生成二维码」：正文选区、输入框 / 文本框里的选区都算；没选中就用当前页地址并提示
- **按住 Alt 悬停链接 0.5 秒**：在链接旁浮出该链接的小二维码，点它放大成完整浮层
  （用户脚本拿不到浏览器原生的右键菜单，用这个手势代替「右键链接 → 生成二维码」）

`@match` 全站，`@noframes`。编码器自己实现，不 `@require` 任何库。
`@grant` 只有 `GM_getValue` / `GM_setValue`（存纠错等级）和 `GM_registerMenuCommand`。

## 编码器怎么实现的

整个编码器是脚本里 `QR-ENCODER-BEGIN` / `QR-ENCODER-END` 两行注释之间的 `const QR = (() => { … })()`，
只用 `TextEncoder`，不碰 DOM / GM —— 测试按这两行标记把它切出来在 node 里直接跑。

| 步骤 | 做法 |
|---|---|
| 模式 | 整段文字挑一个最省的：全是 `0-9` → 数字模式（3 位 10 bit）；全在 `0-9A-Z $%*+-./:` 里 → 字母数字模式（2 字符 11 bit）；否则字节模式，一律 UTF-8，长度字段数的是**字节** |
| 版本 | 从 1 往上试，第一个「模式指示符 + 长度字段 + 数据」放得进 `数据码字数 × 8` 的就是。长度字段位数随版本变（字节模式 1–9 是 8 位，10 起 16 位），所以不能按容量表一次查出来，只能逐个试 |
| 容量表 | 只存「每块纠错码字数」「块数」两张 4×40 的表（标准表 9）；总码字数由公式 `rawDataModules(ver) >> 3` 算（扣掉定位、对齐、时序、格式、版本信息） |
| 补齐 | 终止符最多 4 个 0（放不下就少放）→ 补到整字节 → 交替填 `0xEC 0x11` |
| RS 纠错 | GF(256)，本原多项式 `0x11D`，生成元 α=2；`EXP` 表存两圈省掉乘法里的取模。生成多项式 `∏(x − α^i)`，数据 × x^n 除以它的余式就是纠错码字（就是一个移位寄存器） |
| 分块交织 | 短块在前、长块（多 1 个数据码字）在后；数据码字按列交织，短块缺的最后一列跳过；纠错码字再按列交织 |
| 摆放 | 功能图形先画并标记 → 码字按位从右下角两列一组蛇形上下走，跳过功能格；第 6 列（竖向时序）整体左移一列；剩余位留 0 |
| 格式信息 | `纠错等级(2) + 掩码(3)`，BCH(15,5) 生成多项式 `0x537`，再异或 `0x5412`。纠错等级的编号是 L=01 M=00 Q=11 H=10，**不是**按 L<M<Q<H |
| 版本信息 | 版本 ≥7 才有：6 位版本号 + BCH(18,6) 生成多项式 `0x1F25`，不异或，右上 / 左下各一份 |
| 掩码 | 8 种都试，**画上对应的格式信息之后**算罚分，取最低。异或两次复原，不用每次复制矩阵 |

### 掩码罚分（标准 7.8.3）

| 规则 | 计分 | 实现上的取舍 |
|---|---|---|
| N1 行 / 列同色连续 ≥5 | 3 + (长度 − 5) | — |
| N2 同色 2×2 块 | 每块 3，重叠的分别计 | — |
| N3 1:1:3:1:1（深浅深深深浅深）且一侧有 4 个浅色 | 每处 40 | 符号外是静区，**按浅色算**；两侧都有 4 个浅色就算两处（和 Nayuki 的实现一致） |
| N4 深色占比偏离 50% | 每满 5% 加 10 | `floor(|深色×20 − 总数×10| / 总数) × 10`，正好 55% 算 10 分 |

N3 的边界处理各家实现不一样（node-qrcode 不把静区算浅色），所以**同一段内容不同库选出的掩码可能不同**，
但都是合法的二维码。实测：本脚本和 node-qrcode 在 7 组输入里有 3 组挑了不同的掩码，
强制同一掩码时 56 个矩阵逐位相同。

### 要不要加 ECI 头

字节模式在标准里默认是 ISO-8859-1，严格来说 UTF-8 内容应该在前面加 ECI 26 声明。实际情况：

- 主流生成库（node-qrcode、Nayuki 的 qrcodegen）默认**都不加**；扫码器拿到没有 ECI 的字节数据，
  普遍是「能按 UTF-8 解就按 UTF-8」去猜。
- 有资料提到部分老扫码器不认 ECI，会把 ECI 头当成内容的一部分显示成乱码；ZXing 早年对一段 UTF-8
  中文猜成过 Shift_JIS（2008 年的 issue）。**这两条是公开资料，没有在真机上实测。**
- 本机实测（ZXing-js，html5-qrcode 2.3.8 打包的版本）：中文、日文、`café ñ 😀` 加不加 ECI 都能正确解出。

所以默认不加，`CONFIG.eci = true` 打开后只给含非 ASCII 字符的内容加（纯 ASCII 加了没意义还占 12 位）。
遇到某个扫码器扫中文出乱码，先试打开它。

## 关键的坑

1. **页面 CSP 禁内联样式时，shadow root 里的 `<style>` 一样被拦。** 浮层样式全丢，变成页面底部一坨控件，
   而且不报错，只有控制台一行 CSP 警告。改用构造样式表（`adoptedStyleSheets`），它走 CSSOM 不归 `style-src` 管；
   不支持时退回 `<style>`。测试用 `style-src 'self'` 的响应头复现。
2. **在浮层文本框里打字会触发页面的全局快捷键。** 键盘事件冒出 shadow DOM 时 `target` 被重定向成宿主 `<div>`，
   页面「焦点在输入框里就不处理」的判断认不出这是在打字：GitHub / YouTube 那类 `/`、`j`、`k` 照常触发，
   `/` 还被 `preventDefault` 吃掉、焦点被抢到页面搜索框。在宿主上截住 `keydown/keypress/keyup` 冒泡；
   Esc、Alt+Q 挂在 window 的**捕获**阶段，先于截断执行，不受影响。页面自己挂在捕获阶段的快捷键截不住。
3. **快捷键按 `KeyboardEvent.code` 匹配。** macOS 上 Option+Q 的 `key` 是 `œ`，按 `key` 判断永远对不上。
4. **复制图片：`ClipboardItem` 里直接放 `toBlob` 的 Promise。** Safari 要求 `clipboard.write` 在用户手势里同步发起，
   先 `await` 出 Blob 再写，手势就过期了。`http:` 页面没有 `navigator.clipboard`（非安全上下文），直接降级为下载。
5. **下载用 `<a download>` + blob URL，revoke 延后 10 秒。** 同步 revoke 时 Firefox 会下载失败。
   不用 `GM_download`：blob 地址是页面这边生成的，交给扩展下载在 Firefox 上拿不到。
6. **文本框里的选区：Firefox 的 `getSelection()` 拿不到。** 实测 Chromium 现在能拿到，Firefox 是空串（MDN 记载），
   所以先从 `selectionStart/End` 截；`email`、`number` 类型的 input 读 `selectionStart` 会抛错，密码框不读。
7. **点外部关闭只认「按下也在遮罩上」。** 在文本框里选文字、拖出面板松开时，`click` 的 target 是共同祖先（遮罩），
   只看 `click` 会误关。
8. **canvas 每模块整数像素 + `image-rendering: pixelated`。** 非整数缩放时模块边缘被插值成灰色，手机对着屏幕扫更难对焦。
   显示用的画布是显示尺寸的 2 倍以上（高分屏）；导出约 1024px，仍取模块整数倍。
9. **悬停小卡片：** 鼠标离开链接 0.3 秒后才收起，留时间穿过链接和卡片之间的空隙去点它；
   页面滚动直接收起（卡片是 fixed 的，滚了就和链接对不上了）。用过这个手势时 Alt 的 `keyup` 会 `preventDefault`，
   想挡住 Windows 上 Firefox「单按 Alt 弹出菜单栏」—— **没在 Firefox 上实测**。

## 已知限制

- 不做分段混排（例如 URL 里一长串数字单独用数字模式）。常见输入混排省不了几个字节，换来的复杂度不值。
- 不支持汉字模式（Kanji，Shift_JIS 双字节）：只对日文有用，中文还是走 UTF-8 字节模式。
- 不自动把小写 URL 转成大写去用字母数字模式：路径和参数大小写敏感。
- 纠错等级是用户选的就用那个，不会在「版本不变能放下」时自动升级纠错等级。
- 超过版本 40 容量（M 级 2331 字节，约 777 个汉字）只提示，不拆成多个码。
- 页面挂在捕获阶段的全局快捷键截不住（见坑 2）；`html` 上有 `transform` / `filter` 的页面，按 CSS 规则 fixed 定位的浮层会跟着页面走（推断，没遇到过实例）。
- Firefox 扩展沙箱里构造样式表能否挂到页面的 shadow root 上没实测，失败时会退回 `<style>`（这时 CSP 页面上样式会丢）。

## 测试

```bash
NODE_PATH=/path/to/node_modules node qr-code/test/run.cjs
```

全程离线，页面用 `page.route(/^https:\/\/example\.com\//, …)` 挂在假域名下（**用正则**：glob 对含中文的路径不可靠）。

- **编码器（node）**：和公开样例逐码字比对 —— ISO/IEC 18004 附录的 `"01234567"` 1-M（数据码字 + 10 个 RS 码字）、
  `"HELLO WORLD"` 1-M / 1-Q 的 RS 码字、附录 A 的 7 次生成多项式、表 7 的容量、附录 C / D 的格式 / 版本信息 BCH、
  附录 E 的对齐图形坐标；版本自动选择（刚好放满 / 多一个字节）；4 条罚分规则的单元测试；自动掩码 = 罚分最低。
- **真实解码**：矩阵画到 canvas，交给 ZXing（html5-qrcode 打包的那份）解码，比对原文 —— 纯数字、字母数字、URL、
  中文（加 / 不加 ECI）、emoji、空串、版本 40 满载，以及 8 种掩码 × 4 个纠错等级。
  仓库不带解码器，按 `QR_DECODER` 环境变量 → `require.resolve('html5-qrcode/…')` 找；
  都找不到就跳过这一组（打印提示），其余照跑，UI 用例退化成核对画布尺寸。
  ZXing-js 对个别矩阵在某些像素尺寸下找不到定位图形（32 个里 3 个在 4px/模块时解不出、2px 能解；
  同一矩阵和 node-qrcode 的输出逐位相同），所以解不出时换 2px、3px 重画再解。
- **UI**：浮层打开 / 关闭（菜单、Alt+Q、Esc、点外部）、改文字重绘后扫码、纠错等级切换与记忆、超长提示、
  下载 PNG（读回文件解码）、复制图片（授权剪贴板后读回解码）、两种降级、选中文字、Alt 悬停链接、
  页面全局快捷键、CSP 禁内联样式、`CONFIG.eci` 打开后的容量与解码。
